# 审阅清单修复与运行边界（2026-10-25）

## 已处理的问题

| 项 | 结果 |
| --- | --- |
| R1 | 普通原生发送明确未提交时，临时错误最多3次额外重试（2/4/8秒）；明确终止保留`last_delivery_failure`并释放队列。未知提交仍保留意图，不重发、不回退桌面 |
| R2 | 普通回复及搜索检查模型结束原因；截断、空正文进入有界生成重试，过滤单独报错。内部推理不作为正文，主动沉默仍是结构化决定 |
| R3 | 记忆失败有界重试，通常5次后隔离，已触发学习降级的批次最多8次；认证错误立即隔离。隔离仅保存来源指针与原因，不伪造水位；后续任务可继续 |
| R4 | 每次确认最多2页增量扫描，保留20条重叠；阻塞后15秒补查，新群消息可提前唤醒。每60秒启动分步旧记录审计，每轮最多额外1页，兼顾迟到/更新记录 |
| R5 | 默认总待处理32、同成员8；达到上限时保留未接纳位置，不推进游标。首次已识别且延期的触发不因等待超过90秒被丢弃。最多预生成前4项，发送阻塞后暂停新生成 |
| R6 | 合并索引与已核验原消息的精确缓存候选，索引陈旧或不可读也可回退。优先高清文件，符号链接和跨群猜图仍拒绝 |
| R7/R8 | 共享发送后端枚举，拒绝拼写错误；时间参数拒绝非有限值和布尔值 |
| R9 | 明确点名/引用邀请先由非思考角色判断，通过后创建完整回复任务。图片、搜索、专业长答和记忆沿用主链路；无人邀请的自然插话继续短答 |
| R10 | 原生模式恢复检查账号、消息表与helper健康，不要求AT-SPI群控件可见；桌面模式保留界面检查，客户端仍使用现有显示环境 |

明确未提交且重试耗尽时，不能保证通过同一失效通道发送错误提示，因此只读状态留下明确失败。未知提交不会自动解锁。

隔离记忆任务见`queue-status.memory_quarantined`。后续正常任务可能自然推进水位；隔离不承诺日后自动补记旧来源，也不绕过去重或来源验证。可以查看元数据后决定维护方式。

## 配置和低成本状态

新增`queue.max_pending`、`queue.max_pending_per_sender`、`queue.generation_lookahead`、`queue.intake_max_pages`，默认32、8、4、4。单次接收最多4页，每页最多100条，随后让出主循环。拥塞时保留游标等空位，不无上限地预生成回答。

`target.context_budget_strategy`默认`strict`，保持超预算时不截取历史。显式设为`recent`时，省略完整的旧消息，并告诉模型省略了多少条；当前提问和明确引用保持完整，它们本身超过预算仍报错。这是有标记的历史省略，不是模型生成的事实摘要。

历史附相对提问的秒数，改善停顿和指代理解。`prompts/topic_aliases.json`支持人工维护`groups`，例如`[["Warframe", "星际战甲"]]`；默认空列表，不自动学习别名。只有当前话题和记忆各自明确包含同组别名才增加实体匹配，没有引入向量数据库或额外模型请求。

状态增加拥塞、隔离任务、最近明确发送失败、配置后端和本地告警码。`native_timings_ms`记录最近原生发送的版本核验、Frida附加和提交耗时。不恢复常驻状态面板或周期systemctl采集。

本次先增加细分测量，继续保留完整ELF校验；没有在缺少性能依据时引入跨进程hash缓存。上线后按实测决定是否需要缓存，不把发送耗时当成整机CPU或功耗结论。

## 发布与回滚

新增`scripts/deploy-release.py`，输入为已校验、解包且通过Linux测试的发布目录。默认仅打印计划，`--apply`才执行；root helper变化还需`--update-native-helper`。

```bash
python3 scripts/release.py verify /path/to/release.zip
# 在独立暂存目录以wxbridge运行test-offline.py，通过后：
python3 scripts/deploy-release.py --stage /path/to/stage/app \
  --backup /var/backups/wxbridge/review-release
python3 scripts/deploy-release.py --stage /path/to/stage/app \
  --backup /var/backups/wxbridge/review-release --apply --update-native-helper
```

工具拒绝未审阅的删除路径、私密路径、旧代码hash漂移和覆盖已有备份。保留实际配置、密钥、人格、人工别名、记忆与队列；新增默认别名文件仅在本机不存在时安装。

在队列空闲并取得双锁后更新计划内文件、默认JSON及必要helper资产。失败只恢复代码/清单/helper，绝不覆盖队列或记忆。`restore.json`记录原权限和所有者；新监听必须有新版本心跳。helper健康检查不发送消息、不进行Frida注入。

存在删除文件的发布需另审迁移；本工具不会把尚未上线的本地目录整理混入服务器。主机重启仍会清空tmpfs任务，微信升级仍需重新核对版本指纹。
