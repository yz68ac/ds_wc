# 附件索引缺失时读取已核验缓存

## 问题

引用图片的原消息、作者和图片标识正确，本群磁盘已有可解密的缩略图，但微信附件索引没有对应记录。原实现只通过附件索引构造候选文件，因此返回 `local_image_index_missing`，模型请求中实际图片数为0。

## 修复

附件索引仍为首选。它没有提供有效候选时，允许从当前群内唯一的原图片消息读取protobuf缓存标识，枚举本群已存在的合法月份目录，构造该精确标识的原图、缓存图、预览图和缩略图路径。不同月份之间也按质量排序，不让较新的缩略图遮住已有原图。

回退要求当前群、合法server_id、唯一原消息、图片类型、图片标识与引用作者核验通过。引用快照中的文件名不作为依据；不扫描其他群，不按时间接近或“最近图片”猜测。没有作者证据、原消息歧义、错误群或不匹配标识时不启用回退。

只构造受限目录中的候选，读取仍由已有工作进程执行，并保留大小、完整性、解密和图片尺寸检查。目录或文件的符号链接均拒绝，防止缓存路径跳到另一群或账号外。

成功读取时，安全图片元数据增加 `binding_source=verified_message_cache`；实际质量继续使用 `original/cached/preview/thumbnail`。模型明确收到缩略图及其尺寸，不会将其标为原图。本次不实现自动下载高清原图，低分辨率截图中的小字仍可能无法辨认。

## 验证

合成回归覆盖索引为空时真实图片进入多模态请求、缩略图质量标记、跨月份原图优先、预览缓存、等待文件就绪、错误作者/标识/类型、重复原消息、来源不明缓存名、其他群、非法月份和符号链接。原有索引读取与wxgf解码回归保持。

上线只替换本次修复文件及版本清单，保留实际配置、密钥、人格、记忆、接收游标和运行队列。用既有失败输入在本机重建图片请求，检查实际图片数、质量与尺寸；不补发旧回复。相关链路见 [图片说明](../VISION.md) 和 [发送接口](../NATIVE_API.md)。
