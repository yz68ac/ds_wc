# 成员身份、临时编号与档案数量

长期档案键是机器人账号、目标群及成员稳定微信user_name；昵称和曾用名不作为主键。每轮给模型的U1/U2仅是当前映射，下一轮顺序可能变化，不能作为跨轮人物指代，也不能在群里用它称呼成员。

新记忆摘要按已验证的当轮映射处理：档案主人写“本人”，其他成员编号转为当轮提供的昵称。找不到映射的建议只拒绝该条摘要，其他来源已验证的更新照常处理，接收/记忆水位继续前进，避免毒任务反复重试。芯片U1等本人来源确实出现的真实编号保留，并记录`literal_labels`来源验证标记。

旧摘要没有保存当轮映射，不能按当前U1/U2盲目改名。含未验证临时编号的旧摘要和表达学习记录保留在JSON及私有投影中，标明隔离，不进入主回复或后台整理背景。关系依据中的旧歧义文字仅在传给模型的副本里标为指代不明，原分数与依据不改。TTL、来源ID、好感度、关系历史及接收水位均不因隔离而重置；不会把隔离当成新证据或重新计分。需要修订时依据原消息做显式维护。

状态中`members`表示成员档案数，`members_with_memories`表示有可用摘要的人数，`ambiguous_entries`及`ambiguous_learning`分别表示有效期内因旧编号歧义隔离的摘要/表达记录数。仅有历史互动或头像线索的人也可有档案，因此档案数不等于近期发言人数。可查看文件中的“表达学习”是独立资料区，不算另一个人。`MemoryStore.write_projection()`可在双锁维护窗口重建显示文件，不改权威JSON、水位或修订。

所有回复路径共用内部编号不外显的提示约束；技术编号和用户明确要求引用的原文保留，不做全局正则删除或替换。模型不能按本轮可见编号/资料区块猜群总人数。没有新增润色请求、监控轮询或状态自动刷新。

发布工具默认仍等待全部记忆任务清空。仅在明确使用`--allow-pending-memory`时，可保留尚未运行的持久记忆任务上线；前台任务、生成工作进程、运行中的记忆/参与判断仍须空闲。双锁切换期间校验任务数量和队列元数据不变，恢复后按原水位继续，不删除待整理任务。
