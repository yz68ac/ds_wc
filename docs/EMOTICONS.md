# 微信表情与日常标点

## 配置

实际运行仍用标准JSON的config.json；带注释参考见config.example.jsonc。默认值：

```json
"reply_style": {
  "wechat_emoticons_enabled": false,
  "omit_trailing_period": true
}
```

本次按用户要求在Linux实际配置开启表情。修改这两个开关后重启wxbridge-bot.service；默认JSON不覆盖实际配置同名项。

开启时由原本那次模型请求按语境偶尔选一个微信内置表情，允许接梗时单发表情；有明确事实、操作或安慰需要时仍应回答，不以表情敷衍。普通回复、联网最终回答及主动接话共用规则，不新增挑选表情的API请求，不增加图片或收藏表情发送。

关闭表示禁止模型主动用表情装饰或单回表情；用户明确要求解释、引用、列出表情时仍可给出原文，群友消息也不会被抹除。这是生成表达规则，不是全局删除方括号的过滤器。

omit_trailing_period只处理保守识别的普通短句末尾中文句号“。”，包括表情前后：知道啦。[偷笑]→知道啦[偷笑]，[偷笑]。→[偷笑]。保留问号、感叹号、逗号、省略号和句内句号；代码、命令、链接、小数、引用及专业长答不机械修改，ASCII句点不删除。人格提示也引导日常短答不用尾句号。

## 名称与资料来源

权威数据是prompts/wechat_emoticons.json，加载器位于ai/emoticons.py。2026-10-21只读解析当前/opt/wechat/wechat内置Qt资源：表情面板109项、新版映射45条，存在重叠；资源SHA256及核对日期保存在JSON内。旧表情中文名称也与主程序名称表核对。只维护已核实的20项，未核实的英文别名留空，不靠网上转载清单补造。

每项包括名称、别名、字面形象、常见梗义、场景、避用情况、歧义提醒、合成示例和来源，核对日期共用根字段reviewed_at。程序只注入精简语义和分寸，来源网址与完整示例留供维护，不塞进回答。语义是人工维护的背景数据，不自动联网更新，不让模型自行写库。

客户端映射只证明名称，不证明梗义；多数用法标记为人工归纳，不冒充官方唯一解释。研究依据包括[微信反讽实验](https://pmc.ncbi.nlm.nih.gov/articles/PMC11665359/)、[捂脸真实对话研究](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003339811)、[Doge与正文互动研究](https://benjamins.com/catalog/ip.00124.wu)。最后一项是Bilibili语料，只作跨平台参考；微笑的本项目释义另按用户偏好明确限定。

不能单凭表情认定群友的恶意、性格、恋爱关系或改变好感度，仍以本人文字、关系和场景为准。后台记忆整理也使用同一份语义参考，明确禁止单凭一个表情生成性格或好感度更新；不新增整理请求。语义参考不覆盖人格和事实准确性。
