# 常见问题与已知限制

排障先看服务、`queue-status` 和 `live-status.json` 的安全元数据，不要先重发或删除队列。实际数据库诊断、输入测试和记忆修改前停止监听及恢复定时器；步骤见 [开机恢复](BOOT_RECOVERY.md)。

## 真实 @ 很久不回复

依次区分接收、生成、等待冷却、UI 提交和数据库确认。`queue-status` 可查看任务阶段、有效版本、阻塞原因和最近成功时间，不显示正文。冷却和 API 慢请求会等待，已接纳任务不会因排队超过 90 秒被丢弃。

没有入队时检查客户端是否同步新消息、目标群/登录账号是否正确、消息元数据是否真的包含对机器人稳定 ID 的 @。手打昵称不等于真实 @；首次接收还会过滤自己、无效时间和过旧触发。拍一拍虽然已有解析与调度代码，但实时事件同步尚未稳定验收，不应视作可靠入口。

已生成但没有对应发出记录时，确认发送暂停原因。错误群、来源不明草稿、窗口焦点异常或提交结果不明都会阻止继续发送，保护性暂停不会停止接收新消息。

## 草稿残留与发送确认

历史故障已确认：回复生成后没有对应本人发出记录，旧 GI Text 确认检查曾失效，残留草稿又阻挡后续任务。客户端某些按钮只提供 `SetFocus`，它不能当作点击发送；鼠标已经位于目标坐标时，`mousemove --sync` 也曾导致等待超时。

当前实现区分按钮动作、原生窗口命中、草稿读回和实际发出确认，鼠标定位后核对坐标与活动窗口。只有明确尚未提交的临时故障允许有界重试；点击后结果不明暂停并等待核对，不自动重复发送。

当时 41 字草稿已受控清空，没有补发；首次按钮操作为什么没有提交没有充分证据，不能把后续发现直接当作那次的确定原因。以后遇到不同草稿仍需保护，不应按长度自动清空。

## 图片模糊或不可读

先区分本地只有缩略图、原图尚未下载、引用与附件未绑定、加密格式变化、解码失败，以及模型读图错误。手机上清晰不表示 Linux 缓存已有同一原图。

程序只使用已绑定的本地缓存，有限等待后仍缺失就说明不可读；不会声称已经看过原图。排障参考 [图片链路](VISION.md) 与 `scripts/diagnose-media.py`，不要把真实图片或解密结果上传 Issue。

## 重启后不监听

检查私有挂载、手机登录、数据库是否打开、身份绑定与恢复原因码。整机重启会清空密钥和未完成的内存任务，恢复器需要重新提取密钥。持久游标仅防止重放，不保存旧问题正文。

## 脚本用途

`scripts/diagnose-intake.py`、`diagnose-media.py` 是受控诊断入口，可能读取私密内容；`recover-focus-only.py` 是高级维护脚本，必须按参数核对未决意图，不能作为常规启动步骤。历史一次性切换脚本不作为安装器发布。

提交问题时提供系统、Python、微信版本、提交号、安全原因码和合成复现，按 [安全说明](../SECURITY.md) 排除真实数据。
