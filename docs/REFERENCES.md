# 引用消息并向助手提问

在微信群中长按一条消息，选择“引用”，再从群成员列表真正 @ 助手并输入问题，例如：

```text
@ds 这怎么看
```

程序分别提供“这次新写的问题”与“被引用的内容、作者、原消息时间”，模型可以据此理解“这”。昵称叫 ds 或其他名称不影响触发，判断依据是被 @ 账号的真实 ID；只手打 `@ds`、没有实际选择账号时，不保证存在真实 @ 元数据。

引用是提问者明确指定的内容，因此可以早于默认五分钟群聊上下文。它会作为单独的引用快照提供，不扩大普通历史窗口，也不会搜索其他群、下载文件或自动打开链接。原系统人格、模型、密钥配置保持原值。

| 引用类型 | 提供给模型的内容 |
| --- | --- |
| 文字 | 引用快照中的正文、作者、原时间 |
| 再次引用的文字 | 分层保留引用关系，最多展开有限层数 |
| 链接 | 快照里的标题、摘要、URL；不声称已经读取网页全文 |
| 图片 | 查本群原消息与附件索引，内存解密本地原图/预览/缩略图，随问题传给模型；不可读则明确说明，见 [图片说明](VISION.md) |
| 语音、视频、表情、其他附件 | 明确提供类型和“无可读正文”；目前不识别，不编造内容 |
| 已缺失或无法解析的引用 | 说明引用内容缺失；损坏的引用 XML 不当普通文字触发 |

引用内容计入 `target.context_max_chars` 的用户提示词预算，超出时保留生成失败原因，不静默截断。只给当前提问展开明确引用；历史里其他人以前引用的旧内容不会自动全部带入。

内部会识别微信打包的 64 位 `local_type`（如 `0x3900000031`，主类型 49、子类型 57），把当前问题规范化为可触发的文本；引用中的旧 @ 不会冒充当前消息的真实 @。

每次 @ 仍独立排队，合并保持关闭。新增 `recent_intake` 元数据可在 `queue-status` 与状态文件查看：包括接纳/跳过原因、类型、是否真实 @、引用类型及字符数，不保存正文或密钥。
