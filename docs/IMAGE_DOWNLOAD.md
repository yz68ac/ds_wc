# 引用图片的清晰缓存下载

Linux微信有时只自动收到缩略图。手机能看清不代表Linux本地已有完整缓存；本轮实际引用曾只附送67×144的JPEG。打开相同图片后，本账号对应缓存变为498×1080，经现有wxgf解码链路转为可读PNG。此处称为清晰微信缓存，不保证是发送者上传的原始文件。

## 配置

`vision.download_enabled`默认false；Linux实际配置可设true。`vision.download_timeout_seconds`默认20秒，允许5–30秒。修改JSON后重启监听。

下载路线需要当前微信登录、原生发送后台native_service、X11虚拟显示、窗口管理器及AT-SPI。复用现有Gdk/GdkPixbuf系统库，不新增独立程序。微信启动时须注册无障碍，停用后可能需要重启微信才能恢复；仅重启AT-SPI不保证有效。发送仍走原生接口。

## 执行与校验

主进程先按群、原消息server_id、图片类型、MD5和作者核验引用来源，再把下载证明及已解析群名交给生成工作进程。工作进程不查询微信数据库，不读取CDN凭据，不访问消息里的URL。

只有本地读取结果仍为预览/缩略图时才尝试下载。工作进程取得私有tmpfs中的图片UI锁，选中已核验群，打开聊天记录的Media页，在内存比较对应缩略图与可见媒体项的像素特征。最多检查三屏；平坦图片、匹配不足或多个相似候选均停止，不按时间、位置或“最近一张”猜测。

匹配同时检查RGB误差、空间相关性、图像细节及与第二候选的距离。点击前核对实际X11窗口归属、几何位置及鼠标命中的窗口；Qt关闭窗口后仍可能保留SHOWING无障碍节点，因此还须确认真实窗口存在。只关闭本次操作创建的微信窗口，清理结束后释放UI锁。

打开图片只算触发操作。随后沿原消息绑定的本地缓存路径重新读取、内存解密和验图，取得original/cached质量才报告下载成功。最终发送给模型的图片始终来自原消息绑定缓存，不直接使用屏幕截图。缓存未更新时保留原缩略图及真实质量标记。

截图、解密图片和base64不落盘；像素比较不调用模型。下载失败只返回安全错误码，不阻止文字生成、接收新消息或发送确认。单次生成中多个引用共享下载总时限，生成工作进程的总预算相应增加，主进程轮询继续运行。

## 状态与限制

`last_vision.items[].download`记录outcome及elapsed_ms，常见结果为downloaded、download_unverified、download_busy、download_match_missing、download_match_ambiguous、download_timeout或download_ui_unavailable。不记录聊天、成员ID、图片、路径或凭据。

默认最多三屏，过旧图片或缩略图特征不足可能无法自动定位；此时保留原有降级行为。提高API图像detail不能还原缩略图丢失的细节。兼容下载增加对虚拟桌面组件的依赖，尚未代替为稳定的原生图片下载接口。
