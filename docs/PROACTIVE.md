# 主动接话与短会话

总开关 `proactive.enabled` 默认关闭。实际配置开启后，支持活跃聊天入场、自然称呼/引用入场、低频多人聊天候选，以及发言后的最多两轮接话。配置修改后重启监听。每个候选仍由模型决定说话或沉默，不按关键词直接发固定句子。

## 何时考虑入场

- 保留原门槛：最近五分钟至少十条群成员文字。
- 开启 `opportunities` 时，新消息自然提到配置中的机器人称呼，或明确引用机器人的消息，可单独进入判断。手打称呼只表示主动候选，不冒充真实 @，没有必答承诺。
- 最近五分钟至少三条成员文字、至少两位成员，且有三条未判断的新文字时，可考虑低频聊天中的接话点。仍可沉默，不为凑参与度抢话。

新入场须满足独立入场冷却和每小时预算，实际发送还须满足普通发送间隔；别人明确 @ 其他成员的消息不作为接话目标。称呼使用 `target.bot_name`、`target.trigger.mentions` 去掉 @ 后的别名及 `opportunities.address_names`。ASCII 称呼检查边界，避免把 ads、dss 等误当 ds。

每次判断只调用一次现有模型，同时决定是否开口、回复哪条新成员消息和短句正文。普通聊天使用实际五分钟记录和已有相关记忆，不补虚构提问；新消息必须来自已接收游标内。模型无法选择 BOT、旧消息或虚构消息为目标。

## 发言后怎样接着聊

主动短句或真实 @ 的最终回复经数据库确认后，才开启默认 120 秒的接话窗口。一段短会话最多再接两轮；第一轮接话确认后重新计时 120 秒，第二轮确认后关闭会话，不把轮数重置为零。每轮需要新的成员消息并重新由模型判断；确认前不消耗轮数，也不创建会话。

当前对话对象的新文字可以进入判断；其他人需要自然叫机器人或引用她的话才可加入。程序传入机器人实际发过的文字，模型判断是否真在回应她。时间相邻、同一人发言不等于在和机器人说话；别人明确 @ 或引用其他人不作为回应候选。没有新消息不请求模型，不自问自答，不定时叫人回来。

模型认为无需回应时结束短会话；无人回应则到期退出。主动入场后没有成功接上第一轮，到期检查时会从当时起增加两倍入场冷却的等待（默认再等 600 秒）。达到两轮上限也结束；真实 @ 始终正常处理，并可在最终回答确认后建立新的短会话。这里不包含跨小时/跨天的记事回访。

当前对象没有继续回应而出现三条新的成员文字时，关闭旧短会话；机器人账号人工发出更新的消息也会结束它。新真实 @ 任务会抢占尚未提交的主动短句并结束旧会话。会话结束不等于永久关闭主动功能：之后仍可凭新消息重新寻找入场机会，但需要重新满足冷却、小时预算和候选规则。

## 预算与发送保护

默认滚动一小时最多三次主动入场；从上一次主动入场的数据库发出确认算起，至少相隔 300 秒。普通 @ 回复、搜索提示和后续接话不重置这份冷却，也不占入场次数；不再要求最近五分钟完全没发言。任意消息之间仍遵守 target.cooldown_seconds（默认八秒），生成可以先进行、发送等待冷却。短会话的两轮使用该会话额度，不另算入场。每条通常一句、最多三十字，纯文本，不搜索、不猜未提供的图片，不公开判断理由。

主动判断和短句生成使用 `models.participation`：默认开启思考、深度 high、最多 1200 tokens；请求时限继承 `proactive.timeout_seconds`（默认 30 秒），也可由该角色的 timeout_seconds 覆盖。普通 @ 仍使用独立的 max 配置。判断有新消息及十秒节流；独立入场另受六十秒判断间隔和新消息门槛约束。短会话可以在十秒检查间隔后继续判断。若其他成员已有三条新文字、当前短会话已转走，可在同一次检查中寻找独立入场机会；仍先检查入场冷却和小时预算。机器人最近一次实际发言之前的旧提问仅作语境，不重新当作新回复目标。

有效 API 并发仍遵守最多两个的预算。真实 @ 优先，抢占未提交的主动任务和旧短会话。所有短句使用原 SQLite 队列、目标群、草稿保护、持久发送意图和精确发出确认，不把按钮操作当成成功。

发送前重新读取消息。入场短句生成后新增三条文字，或接话短句生成后出现任何新成员文字，都会取消过时短句；生成后人工从机器人账号发出新的文字或图片，也会取消旧短句或结束当前接话；生成之前已有的正常回复不阻挡入场。来源消失、过期、数据库检查异常均不发送。已存在发送意图的任务必须先核对，不能因新 @ 或窗口到期而盲目重发或撤销不确定操作。

进程重启后保留判断水位、已确认的轮数和小时预算；未提交短句重新核对，已提交短句先核对数据库。会话和来源指针只在原私有内存 SQLite 内保存，账号/群沿用队列身份隔离，不额外持久化聊天。整机重启后这些内存状态清空，重新等待上线后的新消息。

## 配置

| proactive 字段 | 默认 | 说明 |
| --- | --- | --- |
| enabled | false | 总开关 |
| window_seconds | 300 | 最近聊天统计窗口，不用于限制机器人五分钟无发言 |
| min_messages | 10 | 原活跃聊天门槛 |
| check_interval_seconds | 10 | 有新消息时的检查间隔 |
| evaluation_interval_seconds | 60 | 独立入场判断的最短间隔 |
| min_new_messages | 3 | 活跃/低频聊天再次判断所需新文字，也使旧入场短句失效 |
| reply_ttl_seconds | 60 | 生成结果有效期和候选新消息年龄限制 |
| timeout_seconds | 30 | 判断请求时限；models.participation.timeout_seconds 可覆盖，不能超过 reply_ttl_seconds |
| max_reply_chars | 30 | 短句硬上限；过长放弃，不截断 |
| entry_cooldown_seconds | 300 | 距上次独立主动入场确认的间隔；@回复与接话不重置 |
| max_entries_per_hour | 3 | 滚动小时主动入场上限 |
| opportunities.enabled | true | 自然称呼、引用和低频多人聊天候选 |
| opportunities.min_messages | 3 | 低频聊天文字条数 |
| opportunities.min_senders | 2 | 低频聊天成员数 |
| opportunities.address_names | ["ds"] | 附加称呼，最多十项 |
| conversation.enabled | true | 发言后的短会话 |
| conversation.window_seconds | 120 | 每轮确认后等待回应的时间 |
| conversation.max_followups | 2 | 最多额外轮数，只允许一或二 |

新子开关只有总开关开启才生效。要保留原十条消息入场门槛并关闭短会话，将 opportunities.enabled 和 conversation.enabled 都设为 false；小时预算和发送保护仍生效。需要完全还原实验前实现时使用部署备份或 Git 回退点，不删除队列或游标。

实际 `config.json` 可独立调整主动接话思考，修改后重启监听：

```json
{
  "models": {
    "participation": {
      "thinking": "enabled",
      "reasoning_effort": "high",
      "max_tokens": 1200
    }
  }
}
```

thinking 可用 enabled/disabled，reasoning_effort 可用 low/high/max，关闭思考时不发送深度参数。预算不影响 30 字发送上限；判断超时、决策格式不合要求或结果已过期时本次不插话，也不发送内部推理或错误占位句。

`queue-status` 和 `live-status.json` 的 proactive 字段显示阶段、机会类型、计数及安全错误；conversation 字段只显示是否有会话、到期时间及已确认轮数，不显示成员 ID、聊天、草稿或内部推理。outcome 区分 entry_cooldown（入场冷却）、entry_budget（小时预算）、entry_backoff（无人回应后的退让）、evaluation_cooldown（判断节流）、waiting_conversation_reply、below_threshold 和 silent，避免把所有未触发都混成“刚发过言”。真实 @ 流程和后台学习规则不变，主动短句确认本身不额外触发记忆整理。

## 轮询性能

数据库和 WAL 未变时复用私有内存盘的解密副本，有变化时刷新；WAL 处理并非只读取最新一条的恒定成本操作。主动策略不按每半秒调用 API，额外检查受新消息和上述节流控制。需要在实际机器分别测空闲及活跃场景，结合客户端、子进程和数据库大小观察峰值。
