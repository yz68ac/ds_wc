# 主动接话与参与窗口

总开关 `proactive.enabled` 默认关闭。实际配置开启后，支持活跃聊天入场、自然称呼/引用入场、低频多人聊天候选，以及成员活动续期的参与窗口。默认取消每小时三次和最多两轮限制；成员连续安静120秒才退出。配置修改后重启监听。每个候选仍由模型决定说话或沉默，不按关键词直接发固定句子。

## 何时考虑入场

- 保留原门槛：最近五分钟至少十条群成员文字。
- 开启 `opportunities` 时，新消息正文任意位置出现独立的 `ds` / `DS` 等配置称呼，或明确引用机器人的消息，都会按点名邀请优先进入上下文判断。例如“这事让ds来评评”“ds最近怎么不说话”，无需真实 @，也无需刷够十条。若只是无关技术缩写、网址、代码或刷词，模型仍可沉默；不冒充真实 @ 元数据。
- 最近五分钟至少三条成员文字、至少两位成员，且有三条未判断的新文字时，可考虑低频聊天中的接话点。仍可沉默，不为凑参与度抢话。

无人邀请的新入场须满足五分钟独立入场冷却；每小时预算默认关闭，显式配置正数时才启用。新消息点名/引用机器人可绕过入场冷却、小时预算和六十秒入场判断间隔，十秒检查节流和八秒发送间隔仍保留。别人明确 @ 其他成员的消息不作为接话目标。称呼使用 `target.bot_name`、`target.trigger.mentions` 去掉 @ 后的别名及 `opportunities.address_names`。匹配不区分大小写，允许中文相邻，检查ASCII字母/数字/下划线边界，避免把 ads、dss、ds123 等误当 ds。只检查最新正文，不因为历史记录或被引用原文里有ds就再次唤起。

每次判断只调用一次现有模型，同时决定是否开口、回复哪条新成员消息和短句正文。普通聊天使用实际五分钟记录和已有相关记忆，不补虚构提问；新消息必须来自已接收游标内。模型无法选择 BOT、旧消息或虚构消息为目标。

## 两分钟倒计时

真实 @ 被接纳时立即进入参与状态，以该消息的实际发送时间启动120秒计时；当次提问保持前台优先，即使窗口到期仍继续完成已接纳的回答。无人 @ 的自主入场在首句通过数据库确认后开始计时，未提交/未确认的短句不会开启窗口。

窗口内任意群成员的新文字、图片、表情、引用或链接等消息都可以续期。仅使用可信的实际发送时间和新消息ID；机器人发言、拍一拍/系统通知、重复读取的旧消息、无效/未来时间或未知发送者不续期。图片可以续期，不代表模型看到了图片内容；只有文字进入接话判断。接收游标、接纳任务和计时更新同一事务提交。

模型可以接任何成员的新话，不再限制为最初 @ 的对象；仍需有自然接话点，不把每条消息当提问。别人明确 @ 其他人不作为回应目标；引用其他人时只有在新正文中点名ds等称呼，才允许结合引用内容回应。其他成员消息照常续期。模型一次选择沉默或聊天换题，不结束参与窗口。没有新的成员文字不调用判断模型，不自问自答，不定时叫人回来。

连续安静120秒退出，不再额外退让十分钟。退出时记录消息水位，旧记录不能反复重新入场；之后必须有新的候选消息，并重新满足入场冷却和门槛。新真实 @ 会更新邀请、抢占尚未提交的旧主动任务；被抢占的已存在发送意图仍先确认。这里不包含跨小时/跨天的记事回访。

## 预算与发送保护

`max_entries_per_hour=0` 和 `conversation.max_followups=0` 默认表示不限次数；可设正数恢复兼容限制。独立自主入场从上一次主动入场的数据库确认算起至少相隔300秒；真实 @、搜索提示和窗口内接话不重置入场冷却，真实 @ 和窗口内接话也不受它限制。任意消息之间仍遵守 target.cooldown_seconds（默认八秒），生成可以先进行、发送等待冷却。每条通常一句、最多三十字，纯文本，不搜索、不猜未提供的图片，不公开判断理由。

主动判断、关键词点名和短句生成使用 `models.participation`：默认关闭思考、最多256 tokens；保留的 high 值仅供将来开启思考时使用，当前请求不发送 reasoning_effort。请求时限继承 `proactive.timeout_seconds`（默认30秒），也可由该角色的 timeout_seconds 覆盖。普通真实 @ 仍使用独立的 max 配置。判断有新文字及十秒节流；未点名的独立入场另受六十秒判断间隔和新消息门槛约束。机器人最近一次实际发言之前的旧提问仅作语境，不重新当作新回复目标。

有效 API 并发仍遵守最多两个的预算。真实 @ 优先，前台生成和排队期间继续记录成员活动，但不额外启动主动生成。所有短句使用原 SQLite 队列、目标群、草稿保护、持久发送意图和精确发出确认，不把按钮操作当成成功。

发送前重新读取消息。入场短句生成后新增三条文字，或接话短句生成后出现任何新成员文字，都会取消过时短句；生成后人工从机器人账号发出新的文字或图片，也会取消旧短句或结束当前接话；生成之前已有的正常回复不阻挡入场。来源消失、过期、数据库检查异常均不发送。已存在发送意图的任务必须先核对，不能因新 @ 或窗口到期而盲目重发或撤销不确定操作。

进程重启后保留判断水位、窗口与成员活动时间，不以重启时间重置倒计时。补读只允许按实际时间连续续期，跨过两分钟空档的消息不能复活旧窗口。升级时结束旧版“机器人回复续期”的窗口，不把旧计时当成员活动证据，也不改队列任务/游标；旧版十分钟退让状态清除。未提交短句重新核对，已提交短句先核对数据库。会话和来源指针只在原私有内存 SQLite 内保存，账号/群沿用队列身份隔离，不额外持久化聊天。整机重启后这些内存状态清空，重新等待上线后的新消息。

## 配置

| proactive 字段 | 默认 | 说明 |
| --- | --- | --- |
| enabled | false | 总开关 |
| window_seconds | 300 | 最近聊天统计窗口，不用于限制机器人五分钟无发言 |
| min_messages | 10 | 原活跃聊天门槛 |
| check_interval_seconds | 10 | 有新消息时的检查间隔 |
| evaluation_interval_seconds | 60 | 独立入场判断的最短间隔 |
| min_new_messages | 3 | 活跃/低频聊天再次判断所需新文字，也使旧入场短句失效 |
| reply_ttl_seconds | 60 | 生成结果有效期和候选新消息年龄限制 |
| timeout_seconds | 30 | 判断请求时限；models.participation.timeout_seconds 可覆盖，不能超过 reply_ttl_seconds |
| max_reply_chars | 30 | 短句硬上限；过长放弃，不截断 |
| entry_cooldown_seconds | 300 | 距上次独立主动入场确认的间隔；@回复与接话不重置 |
| max_entries_per_hour | 0 | 0不限小时次数；1–12可恢复上限 |
| opportunities.enabled | true | 自然称呼、引用和低频多人聊天候选 |
| opportunities.min_messages | 3 | 低频聊天文字条数 |
| opportunities.min_senders | 2 | 低频聊天成员数 |
| opportunities.address_names | ["ds"] | 句中也可唤起的附加称呼，不区分大小写，最多十项 |
| conversation.enabled | true | 成员活动续期的参与窗口 |
| conversation.window_seconds | 120 | 连续无成员新消息多久退出，成员消息按实际发送时间续期 |
| conversation.max_followups | 0 | 0不限接话轮数；1/2可恢复上限 |

新子开关只有总开关开启才生效。要保留原十条消息入场门槛并关闭参与窗口，将 opportunities.enabled 和 conversation.enabled 都设为 false；冷却和发送保护仍生效。需要完全还原实验前实现时使用部署备份或 Git 回退点，不删除队列或游标。

实际 `config.json` 可独立调整主动接话思考，修改后重启监听：

```json
{
  "models": {
    "participation": {
      "thinking": "disabled",
      "reasoning_effort": "high",
      "max_tokens": 256
    }
  }
}
```

thinking 可用 enabled/disabled，reasoning_effort 可用 low/high/max，关闭思考时不发送深度参数。预算不影响 30 字发送上限；判断超时、决策格式不合要求或结果已过期时本次不插话，也不发送内部推理或错误占位句。

`queue-status` 和 `live-status.json` 的 proactive 字段显示阶段、机会类型、计数及安全错误；conversation 字段显示是否有窗口、计时基准 activity_at、到期时间、来源类型及已确认接话数，不显示成员 ID、聊天、草稿或内部推理。outcome 区分 entry_cooldown（入场冷却）、entry_budget（仅启用小时限制时）、evaluation_cooldown（判断节流）、waiting_conversation_reply、below_threshold 和 silent，避免把所有未触发都混成“刚发过言”。真实 @ 流程和后台学习规则不变，主动短句确认本身不额外触发记忆整理。

## 轮询性能

数据库和 WAL 未变时复用私有内存盘的解密副本，有变化时刷新；WAL 处理并非只读取最新一条的恒定成本操作。主动策略不按每半秒调用 API，额外检查受新消息和上述节流控制。需要在实际机器分别测空闲及活跃场景，结合客户端、子进程和数据库大小观察峰值。
