# SSH 交互状态面板

Linux 服务器已有 Python curses 标准库时不需额外依赖。在 `/opt/wxbridge`，以root登录SSH后执行：

```bash
cd /opt/wxbridge
runuser -u wxbridge -- python3 -m wxbridge status
```

已经是wxbridge用户时直接用 `python3 -m wxbridge status`。通过单条SSH远程命令启动需要 `ssh -t` 分配终端；终端使用UTF-8，TERM须能被本机terminfo识别。

## 页面与操作

| 按键 | 功能 |
| --- | --- |
| 1 | 概览：心跳、服务、收发和后台状态 |
| 2 | 待回复任务、分片进度、错误和最近接收判定 |
| 3 | 本次监听进程的模型调用/用量与阶段耗时；面板启动时配置参考 |
| 4 | 记忆队列、整理/恢复状态、表达学习计数、主动参与和窗口倒计时 |
| 5 | 近期安全运行事件，最新在前 |
| Tab / 左右方向键 | 前后切页 |
| 上下方向键 / j、k / PgUp、PgDn | 滚动 |
| g / G | 顶部 / 底部 |
| 空格 | 暂停或恢复自动采集 |
| r | 立即刷新，包括服务与日志；暂停时也可手动刷新 |
| ? / h | 帮助 |
| q / Esc / Ctrl+C | 退出面板，原机器人服务继续运行 |

默认每秒读取一次状态快照，服务与运行事件每五秒采集一次。可用 `status --interval 2` 调整为两秒，允许0.5–30秒。暂停时显示的是冻结的采集时刻；恢复后重新采集。窗口缩放会重排长行，小终端可滚动查看。

无需交互终端的一次性文本输出：

```bash
python3 -m wxbridge status --once
```

原有 `queue-status` JSON接口保持不变。面板只读 `state_file` 同目录的 `live-status.json`、`boot-status.json` 和配置的 `log_file`，调用固定的 `systemctl show` 读取三个服务；不刷新解密副本、不查询微信或队列数据库、不写状态、不启动监听或调用模型。可以在监听运行时查看。

## 状态的含义

心跳超过十秒、监听已停止、systemd不活跃或PID与快照不一致时会明确提示，避免把最后一份旧数据当成当前在线。状态文件尚未生成、格式错误或权限不足时显示原因，其他可读信息仍可查看。systemd不可用时面板仍能显示状态文件。

模型用量属于本次监听进程，服务重启会清零，被取消的请求可能没有返回用量。模型参数明确标为面板启动时的配置参考；修改配置后须重启监听，重开面板才能读取新的配置参考。主程序不在快照里保存API密钥。

运行事件页只提取已知的生成、发送、确认、记忆及参与事件和允许的字段；原始异常、聊天正文、未知日志和终端控制序列不直接显示。原始日志仍可按现有运维方式查看。面板本身不保存终端录制或运行数据。

本轮提供查看和导航功能，没有服务启停、重发、清队列或记忆修改操作。继续使用已有受控维护命令完成修改。
