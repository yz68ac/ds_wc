# 人物关系与短期情绪

关系按现有机器人账号、群和成员稳定 user_name 隔离，昵称变化不重置。沿用后台 memory 请求及 max 思考，不增加独立模型调用；当前回答读取已有状态，后台更新供下一轮使用。@回复确认和活跃闲聊整理共用这些规则。

| 维度 | 初始值 | 证据和变化 |
| --- | --- | --- |
| 好感 | 保留原值，新人50 | 本人实际互动；每批最多±3，每天累计绝对变化最多10 |
| 信任 | 50 | 边界是否被尊重、交流可靠性；仅明确证据，每批±1，每天累计绝对变化最多3 |
| 熟悉 | 0 | 程序按本人有效新文字的跨场景互动积累，模型不能指定数值 |
| 情绪 | 无 | 机器人对该成员的开心、被逗乐、害羞、无奈或不悦；最长3小时 |

信任与熟悉不会因无人发言自动扣分；好感沿用连续14天无互动后，每再满7天向50回归1分的规则。头像只提供弱视觉参考，不参与这些维度的计分。

## 好感的十档表达倾向

| 分数 | 档位 | 主要表达选择 |
| --- | --- | --- |
| 0–9 | 明显疏远 | 平静答必要内容，不主动延续 |
| 10–19 | 保持距离 | 礼貌确认，回应后自然结束 |
| 20–29 | 有所保留 | 愿意回应观点，表达克制 |
| 30–39 | 平淡相处 | 随口评价话题，少个人关心 |
| 40–49 | 普通相处 | 自然平等，有自己的态度 |
| 50–59 | 相处轻松 | 随意接梗，顺势调侃 |
| 60–69 | 有些好感 | 接住明确表达的感受 |
| 70–79 | 更加在意 | 贴题关心，留意实际难处 |
| 80–89 | 亲近偏爱 | 少客套，关心藏在话里 |
| 90–100 | 很亲近 | 示弱时柔软，示好时亲近 |

每10分一档，100并入90–100。新人仍为50，已有好感数值按新档位解释，不修改评分与遗忘规则。

档位只是渐变的语气参考。熟悉不足时保留分寸，关系亲近不自动代表接受暧昧或挖苦；明确称呼、玩笑及回应偏好优先。低好感仍明确回复真实@、保证事实准确，不以漏任务或故意答错表达冷淡。信任较高也不免除事实核实。

## 证据、去重与修正

模型的 affinity / relationship.trust 建议包含 delta、reason、sources、event、strength、revises。event简短概括同一具体事件，同一事件沿用已有表述；strength为weak或clear。弱好感证据至多±1，弱信任证据不计分。普通提问、意见不同、纠正ds、未回复或拒绝暧昧不自动扣分；含糊的调侃可仅形成短期情绪。

来源必须是该成员本人未处理的新文字。机器人输出、旧记忆、引用转述、拍一拍、头像、单独微信表情或Unicode表情不能作为关系变化的证据。程序按来源水位和消息ID去重，另外限制同一成员同一维度十分钟内至多一次变化；对最近保留的30条依据，七天内相同event或相同来源正文的指纹不重复计分。语义相同而措辞不同的事件仍须模型结合近期依据归并，这部分无法仅靠字符串保证。

发现误会时使用明确的新本人来源和revises关联同一成员、同一维度的已有证据ID，提出方向相反且不超过原实际变化的抵消增量。历史保留，目标证据只能修正一次，仍受每批及每日额度限制。此时可越过事件和十分钟去重，以便及时纠正。不会直接删除历史或无条件退回任意分数。

每天额度按来源消息的主机本地自然日结算，涨跌均消耗额度。依据保存实际变化、事件摘要、来源ID、准确时间和修订链接，最多30条；不保存原文或内部推理。重复正文只保存SHA-256指纹。批次中任何校验失败都不提交部分更新。

## 熟悉度与情绪期限

熟悉度每个自然日首个有效场景加2，后续相隔至少30分钟的不同场景加1，每日最多3，总值最多100。纯表情、重复来源不增加；三十天内相同标准化正文不重复累计。后台仅处理尚未接纳过的新文字，不回扫旧聊天。0–9初识、10–29有些熟悉、30–59熟悉、60–100很熟悉。

情绪记录state、intensity、reason、sources，程序按实际来源时间设置三小时有效期；过半时间后语气参考减弱，到期不注入并由常规清理删除。有新澄清可用neutral提前缓和；null表示保持原状。情绪不自动修改好感或信任，不迁怒其他成员，群里不公开心理判断或打分过程。

## 数据与维护

权威文件仍是私有 memory.json，保留schema=1和原affinity字段，新增person.relationship（version=1）。旧记录保留好感、别名、摘要及处理水位，新增信任50、熟悉0、无情绪；不推测旧互动的新分数。常规清理或下一次有效整理原子补齐。只读查看不会触发写入。

additional_prompt.md显示各维度及近期变化依据，供维护查看；实际给聊天模型的内容只包含自然语言关系、相关偏好和短期情绪，不包含分数或计分历史。仍受1200字符总记忆预算约束，不截断原聊天。

原memory status/show/forget/clear命令继续可用。停止监听并取得原单实例锁后，可用 `python3 -m wxbridge memory forget --member wxid_xxx --entry relationship` 重置该成员关系（好感50、信任50、熟悉0、清情绪），保留昵称、事实和偏好，并保留处理水位。整人成员遗忘会同时删除所有关系维度。

本轮阈值集中在 `wxbridge/storage/relationships.py`，未增加复杂配置组合。部署前备份私有记忆；回退代码时保留实时数据，新字段可被旧版忽略，不用旧快照覆盖新收发进度。

## 整理预算与失败诊断

后台max思考与结构化正文共享输出预算，默认改为8192 tokens、90秒总时限（配置允许256–8192 tokens、1–120秒）。主回复和参与判断预算不变，前台抢占及总并发限制继续生效。max_tokens是上限，不要求用满。

结构化整理显式拒绝finish_reason=length的截断结果，报告memory_output_limit并保留任务重试，不尝试写入部分JSON。网络、HTTP、工作进程超时及JSON格式错误分别使用安全错误码，日志和状态不包含模型正文或内部推理。

若同一批次累计失败至少三次且最近原因为表达学习校验，下一次请求只整理人物记忆与关系，本批learning必须为空；它使用明确收窄能力的新请求，旧失败结果仍不提交。新请求可立即尝试，仍受前台优先与整理间隔约束。下一批表达学习正常开启，不放宽来源和观察规则。该批未学到的表达只能由后续新来源再学习，状态memory_recovery记录原因和完成阶段，避免一个无法合法归纳的表达长期堵住人物记忆。

来源/成员匹配错误反复出现时也进入该批恢复，并暂不提供旧对白，只使用本人新发言及已有摘要。正常请求显式提供source_ids_by_member白名单，只列有新发言的可更新成员；已经处理过的晚同步消息在对白中也标为只读。历史成员的纯空占位更新可忽略，不结算分数或刷新互动时间；任何有内容的更新仍必须满足本人新来源校验。
