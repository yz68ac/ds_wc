# 按需联网搜索

继续使用 `deepseek-flash` 和 OpenAI 格式 `/chat/completions`，保留图片理解。模型获得 `web_search`、`web_fetch` 两个函数工具；普通闲聊直接回答，用户明确要求搜索或问题需要最新资料时，由模型请求工具。只修改提示词无法替代工具执行。

## 群聊表现

真实 @ 助手询问近期消息、天气、产品更新等问题。默认直接执行搜索，只发送最终回答和实际网页来源，不先发“我去看看”“我上网搜搜”等等待提示。普通接梗结合聊天语境直接回应；明确询问梗的出处或含义且需要核实时才搜索。

显式设置 `search.feedback_enabled=true` 可以恢复提示。开启后每个问题最多一条，后续搜索或抓取不反复通知。提示与最终回复都走现有目标群/草稿保护、发送意图和数据库确认；提示确认不会消耗最终回答分片。查询工作独立运行，不等待微信界面操作。

可选提示与最终回复之间仍遵守默认 8 秒冷却。关闭提示时不再为等待短句多占一个发送间隔；其他消息的正常冷却继续生效。尚未提交的旧提示不会补发；已有发送意图的提示仍先核对发出记录，不盲目撤销或重发。未知发送状态继续暂停后续发送并接收新问题。

搜索失败、无结果或整理回答超时会明确说明，不能把模型记忆冒充实时核实。保留人格和口语偏好，普通短答通常一句、尽量不超过 30 字；专业或需要证据解释的问题按必要程度展开，避免大段模板化回答。适合时分成两个短段，沿用现有分片规则。成功时只另附一条主要来源的原始网址，已抓取的网页优先，不附长标题或来源清单。网页内容按外部资料处理，不作为系统指令。

所有模型回复（包括关闭搜索时）都要求纯文本，禁止 Markdown 标题、加粗、表格、代码围栏和链接语法。`ai/output.py` 在提示词之外再清理偶发的 Markdown 格式，保留可读正文、代码内容和实际网址；不硬截断正文，不增加一次压缩模型调用。字数是生成偏好，不是截断上限。

## 实现与配置

- `ai/client.py` 的 `complete()` 保留工具调用与思考字段；`chat()` 保留原先只返回最终正文的用法。
- `ai/search.py` 负责有界工具循环、DeepSeek Search/Fetch 请求和来源。搜索只带模型提取的当前问题必要关键词，不自动发送群聊全文；只允许抓取本轮搜索已返回的公开链接。
- `app/workers.py` 在实际调用搜索前发送进度事件，API 子进程继续查询；不查询微信数据库或操作 UI。
- `app/bot.py` 接收内部事件，只有开启反馈才入队提示；`storage/journal.py` 持久化发送意图、确认进度和安全搜索统计，关闭提示不影响搜索统计。

| `search` 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 启用按需搜索；关闭后沿用原单轮模型回答 |
| `base_url` | `https://api.deepseek.com` | 独立 Search/Fetch 服务；使用现有 DeepSeek Key |
| `timeout_seconds` | `15` | 搜索/抓取单次请求超时，允许 1–60 秒 |
| `total_timeout_seconds` | `120` | 包括模型与工具循环的整体时间预算，允许 15–300 秒；工作进程另有 15 秒清理余量 |
| `max_tool_rounds` | `2` | 最多工具轮数，允许 1–3；之后要求最终回答 |
| `max_requests` | `3` | 每个问题最多搜索/抓取工具调用数，允许 1–5；瞬时网络错误每调用最多尝试两次 |
| `max_results` | `5` | 每次搜索返回条数，允许 1–10 |
| `feedback_enabled` | `false` | 默认只发最终回答；显式开启才发单独的等待提示 |
| `feedback_phrases` | 三条默认短句 | 按任务轮换，非空列表，每句 1–80 字 |

配置变更需重启。网页文字按固定预算裁剪，图片和 API 请求总体限制沿用现有规则。查询词、网页正文和来源仅在生成进程内处理，不写入日志或 SQLite；最终回答及其来源按既有分片机制在任务完成后清除。`queue-status` 的 `last_search` 和各任务 `search` 只显示是否尝试、调用数、来源数和错误码，`notice_state`、`intent_kind` 显示提示确认进度，不含提示正文。

协议依据：[DeepSeek 网页搜索与抓取](https://api-docs.deepseek.com/zh-cn/guides/search/)、[工具调用](https://api-docs.deepseek.com/zh-cn/guides/tool_calls/)（2026-10-20 核对）。Search/Fetch 使用相同 Bearer Key，按请求另行计费，模型 token 费用照常计算。
